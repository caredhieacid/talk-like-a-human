# AI 腔：常见套路和改法

AI 腔是模型反复使用的一套固定写法。单独出现一个不算问题；几种一起出现，读的人一眼就能认出来，然后开始跳着读，也不太信里面的内容。

这份文件不用每次都读。写宣传文案、对外公告、社交媒体帖子，或者用户说“AI 味太重”“读着像 ChatGPT”时再来查。

前几类是拿人写的文章对照测过、差别最大的；后面几类没有找到单独的测量，按常见程度排。数据来源见仓库里的 `research/similar-skills.md`。

## 先记住四条

1. **看成批出现的，不抓单个词。** 一个“总之”、一处“不是……而是……”都没问题。几种套路挤在一篇里，才是 AI 腔。
2. **每句话都要给读者一点新东西。** 复述问题、重讲读者已经知道的背景、把刚说过的意思再总结一遍，这些句子删掉。
3. **换成具体内容，不换成另一个套话。** “总之”改成“总而言之”，“赋能”改成“助力”，“seamless”改成“effortless”，都不算改。说不出具体内容的句子，直接删。
4. **不做表面功夫。** 下面这些做法，同类项目拿人写的文章对照测过，都没用，有的反而更糟：禁用破折号、删光副词、硬造长短句交错、把被动句全改成主动、删光“或许”“往往”“perhaps”、故意加口语词或错字、轮换近义词。“一、二、三”这样的序号标题和“这意味着”人写文章也常用，不用改。目标是读者读得懂、信得过，不是骗过检测工具。

## 改的顺序

1. **先看第一句和最后一句。** 第一句应该是答案或最重要的事；最后一句应该是一条信息或下一步，不是总结、客套或拔高。
2. **再看结构。** 几百字的东西切成了几节？每节都配加粗小标题和 emoji 吗？
3. **最后看句子。** 假对比、点明意义、用冒号卖关子、凑数的排比、空洞的形容词。

## 常见套路

每类先写中文和英文的典型说法，再写怎么改、什么时候可以留。

### 1. 先否定一个没人说过的说法

- 不是……而是…… / 不仅仅是……更是…… / 不是 A，不是 B，而是 C / 与其说……不如说……
- It's not just X, it's Y. / X isn't about Y. It's about Z. / rather than merely / should be treated as X rather than Y

这是中英文里测出来差别最大的一类。改法：直接说它是什么。

- ❌ 这不是一次普通的版本更新，而是一次体验的全面升级。
- ✅ 这个版本加了离线地图，没有网络也能导航。
- ❌ This isn't just an update. It's a whole new way to work.
- ✅ You can now edit the same document with up to 10 people at once.

可以留：读者真有这个误解，你在纠正它。比如用户以为是缓存问题，你查出来是权限问题，“不是缓存，是权限”就该这么写。

### 2. 替读者点明意义、做总结

- 这一点非常重要 / 这背后反映的是…… / 这也解释了为什么…… / 这标志着……迈入新阶段 / 具有深远的意义
- This matters. / Here's why this matters. / This underscores the importance of… / stands as a testament to / marks a significant milestone
- 每段最后一句都要拔高一下；文末一段把前文再讲一遍

改法：把事实写出来，读者自己会判断它重不重要。不要写“具有里程碑意义”，直接写它让谁第一次能做成什么。最后一段如果只是在重复，删掉。

可以留：读者确实需要你帮他下判断，比如“所以这个 bug 会影响所有付费用户”，这句给了新信息。

### 3. 结构切得太碎

- 几百字也分成五六节，每节一个加粗小标题
- emoji 当项目符号：✅ 🚀 💡 🔥
- 每条要点都以“**加粗标签：**”开头
- 本来是一段因果，被拆成几个没有动词的短语
- Title Case For Every Heading（英文）

改法：讲因果用段落，列并列的东西才用要点。短回复不用标题。

可以留：“一、二、三”这样的序号标题本身没问题，人写长文也常用。问题是短文被切碎，不是用了序号。

### 4. 用冒号或设问卖关子

- 核心是：…… / 真相是：…… / 答案很简单：…… / 那么问题来了 / 结果呢？……
- Here's the thing: / The kicker? / The result? / The answer is simple:

改法：直接陈述，读者不需要先被吊胃口。冒号本身没问题，用来列举、引出原话都正常。

### 5. 开头结尾的套话和讨好

- 开头：好问题！/ 当然可以！/ 你说得太对了！/ 下面我将从以下几个方面为你详细介绍
- 结尾：希望对你有所帮助 / 如果还有其他问题，欢迎随时提问
- Sure! Here's… / Great question! / You're absolutely right! / I hope this helps! / Let me know if you have any other questions.

改法：第一句直接给答案。说完就停；有具体的下一步，或者要问读者一个信息才能答得更准，就直接写出来。用户说得对，就照着做；不对，就说哪里不对。

### 6. 复述读者已经知道的

- 你问的是…… / 根据你提供的信息…… / 正如你提到的……
- As you mentioned, … / Based on the information you provided, …

改法：删掉，直接回答。读者刚说过的话，不用再念给他听。

### 7. 凑数的排比

- 更快、更稳、更省心 / 高效、便捷、智能 / 精准高效、安全可靠、简单易用
- fast, reliable, and scalable / streamline, optimize, and empower / simple, powerful, and secure

改法：只留有事实撑得住的那一个，并说出事实。“更快”快了多少？“更稳”少出了什么问题？

可以留：三样东西本来就是三样，比如“支持 Windows、macOS 和 Linux”。

### 8. 纯程度的夸饰和宣传词

- 完美融合 / 极致体验 / 全面提升 / 全方位 / 一站式 / 颠覆 / 重新定义 / 开启……新体验 / 强大 / 无缝
- seamless, robust, powerful, cutting-edge, game-changer, revolutionize, unlock, elevate, supercharge, transformative, thrilled to announce, excited to share

改法：去掉只表示程度的词，留下能核对的事实和承诺。“完美融合”改成“融合”，再说清融合了什么；“全面提升性能”改成具体快了多少。更多例子见 [zh-jargon.md](zh-jargon.md) 和 [en-jargon.md](en-jargon.md)。

### 9. 绕开“是”和“有”，或者让数据、市场“开口说话”

- 扮演着重要角色 / 起到了……的作用 / 作为……的存在 / 数据告诉我们 / 市场在呼唤
- serves as / boasts / plays a key role in / the data tells us / the numbers speak for themselves

改法：能用“是”“有”“让”说清的，就用“是”“有”“让”。“这个模块扮演着鉴权的角色”改成“这个模块负责鉴权”；“数据告诉我们”改成“数据显示”，或者直接说数据是多少。

### 10. 信号词

- 值得注意的是 / 需要指出的是 / 不得不说 / 毫无疑问
- It's worth noting that / Notably, / Importantly, / Essentially, / Ultimately, / At its core,

改法：删掉以后意思不变，就删。后面跟着的内容要是真重要，靠内容本身说明，不靠“值得注意”。

## 词表会过时

delve、tapestry 这些词在 2023—2024 年特别多，现在最新的模型用得比人还少；新模型又有新的口头禅，比如 2026 年有的模型写“this matters”比人多一百多倍。中文的“赋能”“闭环”拿同题材的人写文章对照，已经看不出差别，它们的问题是说不清意思，按黑话处理就行。

所以不要追着词表删词。看句子有没有说出具体内容，比记住哪些词“像 AI”有用得多。
