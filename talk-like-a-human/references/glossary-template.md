# 术语表模板

项目里概念一多，就该有一份术语表，规定每个东西叫什么。放在项目根目录的 `GLOSSARY.md`，或者 `docs/glossary.md`。

## 怎么写

- 一个概念一行。
- “标准叫法”是给人看的文字（文档、界面、汇报）里固定用的名字。
- “不要用的叫法”是项目里出现过、或者容易混进来的其他说法，用顿号或逗号隔开。
- “代码里叫”写类名或字段名。**不要把代码名放进“不要用的叫法”**，否则脚本会把代码里的正常用法也报出来。
- “意思”用一两句话说清它是什么，以及容易和什么混淆。
- “例外”可选，写“不要用的叫法”在哪些词里是正常用法，比如“空间”在“存储空间”里没问题。脚本碰到例外里的词就不报。
- 新概念第一次出现时，先在这里加一行，再去写文档。

`scripts/check_terms.py` 会读取表头含有“标准叫法”和“不要用的叫法”的表格（英文表头写 `Use` 和 `Avoid` 也可以），“例外”列（英文 `Exceptions`）可选。其他列随意。

还没定下标准叫法时，可以先把几种叫法随便填进表里，用 `--count` 统计每种叫法用了多少次、在哪些文件，再和团队商量用哪个。

## 模板（复制到项目里改）

```markdown
# 术语表

同一个东西只用一个叫法。加新概念时，先在这里加一行。

| 标准叫法 | 不要用的叫法 | 例外 | 代码里叫 | 意思 |
| --- | --- | --- | --- | --- |
| 工作区 | 空间、项目组、团队空间 | 存储空间、磁盘空间 | `Workspace` | 用户创建的一组项目和成员。计费按工作区算。 |
| 成员 | 账号、组员 | 账号密码 | `Member` | 被邀请进某个工作区的人。“用户”只指注册了产品的人，两者不要混用。 |
| 灰度发布 | 小流量、灰度上线、金丝雀 | | `Rollout` | 新版本先只给一部分用户用。全部用户都能用叫“发布”。 |
```

英文项目可以用这样的表头：

```markdown
| Use | Avoid | Exceptions | In code | Meaning |
| --- | --- | --- | --- | --- |
| workspace | space, project group, team space | disk space, storage space | `Workspace` | A set of projects and members. Billing is per workspace. |
```

## 脚本误报怎么办

- 中文是按字面匹配的，比如“空间”也会匹配到“存储空间”。经常出现的正常用法，写进“例外”列。
- 偶尔一处正常用法，在那一行加上 `check-terms: ignore`，脚本就跳过这一行。
- 一整段都不想检查（比如引用的外部文字、历史记录），在段前加一行 `check-terms: off`，段后加一行 `check-terms: on`。Markdown 里可以写成注释：`<!-- check-terms: off -->`。
- Markdown 里用反引号包起来的代码和代码块，脚本不检查。
